## Why this is separate from kr_features

The existing `kr_features.add_basic_momentum()` is part of the live research
feature semantics and must not be silently changed. It currently uses:
- month-offset windows;
- simple asset-return minus benchmark-return RS;
- downstream missing-value zero fill.

Those semantics may remain valid for the existing model, but they are not the
shared U.S./Korea A3 market contract.

This strict adapter instead requires exact 20/60/120/240 KRX trading-session
windows and computes:

`log(1 + asset return) - log(1 + benchmark return)`

Missing sessions fail closed.

## Benchmarks

- KOSPI names -> KOSPI200 / KRX 1028
- KOSDAQ names -> KOSDAQ150 / KRX 2203

The asset and benchmark must both end on the requested completed session and the
asset must contain every one of the benchmark's final 241 sessions.

## Source provenance boundary

The existing `kr_pykrx_client` can use pykrx first and FinanceDataReader as a
fallback but does not persist original provider response bytes or identify which
provider produced a returned cached frame.

This implementation therefore does **not** label the source as raw KRX/FDR
evidence. It records:
- `provider_identity=UNRESOLVED_PYKRX_OR_FDR`;
- exact normalized parquet cache bytes copied content-addressed into the attempt;
- cache SHA-256;
- a deterministic date/close normalized-frame SHA-256.

That is sufficient for reproducibility of this research proxy, but not for
promotion to a reviewed cross-market A3 market artifact without a later source/
corporate-action review.

## Completed-session rule

Without an explicit `--session`, the collector uses Korea time and will not
consider the current calendar day before 16:30 KST. It then resolves the last
observed KRX business day through the existing KOSPI-calendar client.

An explicit completed session may be supplied for replay/review.

## Corporate actions / return basis

Output is labeled `KRX_OR_FDR_CLOSE_PROXY_UNREVIEWED` and
`corporate_action_status=UNREVIEWED`.

No claim is made that the existing client close series is total-return or a
fully audited split/corporate-action series. That gap must be resolved before
the shared A3 reviewer may relabel the snapshot.

## Automation

The normal repository Smoke Test runs the strict synthetic contract tests.
A separate source-capture workflow has no cron; it runs once after relevant
code merges to main or by explicit workflow dispatch.

The capture artifact contains:
- manifest;
- per-ticker and benchmark receipts;
- content-addressed normalized parquet caches;
- normalized date/close JSON;
- code SHA and source-file hashes.

Provider/network failure or incomplete coverage makes the capture BLOCKED.
