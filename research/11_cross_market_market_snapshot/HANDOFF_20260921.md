## Why this is separate from kr_features

The existing `kr_features.add_basic_momentum()` is part of the live research
feature semantics and must not be silently changed. It currently uses:
- month-offset windows;
- simple asset-return minus benchmark-return RS;
- downstream missing-value zero fill.

Those semantics may remain valid for the existing model, but they are not the
shared U.S./Korea A3 market contract.

This strict adapter instead requires exact 20/60/120/240 KRX trading-session
windows and computes:

`log(1 + asset return) - log(1 + benchmark return)`

Missing sessions fail closed.

## Benchmarks

- KOSPI names -> KOSPI200 / KRX 1028
- KOSDAQ names -> KOSDAQ150 / KRX 2203

The asset and benchmark must both end on the requested completed session and the
asset must contain every one of the benchmark's final 241 sessions.

## Source provenance boundary

The existing `kr_pykrx_client` can use pykrx first and FinanceDataReader as a
fallback but does not persist original provider response bytes or identify which
provider produced a returned cached frame.

This implementation therefore does **not** label the source as raw KRX/FDR
evidence. It records:
- `provider_identity=UNRESOLVED_PYKRX_OR_FDR`;
- exact normalized parquet cache bytes copied content-addressed into the attempt;
- cache SHA-256;
- a deterministic date/close normalized-frame SHA-256.

That is sufficient for reproducibility of this research proxy, but not for
promotion to a reviewed cross-market A3 market artifact without a later source/
corporate-action review.

## Completed-session rule

Without an explicit `--session`, the collector uses Korea time and will not
consider the current calendar day before 16:30 KST. It then resolves the last
observed KRX business day through the existing KOSPI-calendar client.

An explicit completed session may be supplied for replay/review.

## Corporate actions / return basis

Output is labeled `KRX_OR_FDR_CLOSE_PROXY_UNREVIEWED` and
`corporate_action_status=UNREVIEWED`.

No claim is made that the existing client close series is total-return or a
fully audited split/corporate-action series. That gap must be resolved before
the shared A3 reviewer may relabel the snapshot.

## Automation

The normal repository Smoke Test runs the strict synthetic contract tests.
A separate source-capture workflow has no cron; it runs once after relevant
code merges to main or by explicit workflow dispatch.

The capture artifact contains:
- manifest;
- per-ticker and benchmark receipts;
- content-addressed normalized parquet caches;
- normalized date/close JSON;
- code SHA and source-file hashes.

Provider/network failure or incomplete coverage makes the capture BLOCKED.


## 2026-09-21 H1 KOSDAQ150 source repair

Post-merge capture exposed a real defect: the old FinanceDataReader fallback mapped
KRX index code `2203` to `KQ150`, which reached a Yahoo path that returned 404.
The H1 repair keeps the benchmark identity unchanged and routes the fallback through
FinanceDataReader's explicit `KRX-INDEX:2203` reader, which uses the KRX index
history contract (MDCSTAT00301).

Safety boundaries:
- no ETF or KOSDAQ Composite substitution;
- no zero fill;
- KOSDAQ150 receives a new source-segregated cache name so an old KQ150/Yahoo
  cache cannot be reused;
- a sidecar receipt records the normalized source identity and is required for
  cached 2203 replay;
- the receipt says `raw_source_claimed=false`: this is normalized provider
  evidence, not archived raw KRX bytes;
- all outputs remain `UNREVIEWED_CLOSE_PROXY`, selector-ineligible and
  portfolio/order authority stays zero.

A real capture must still prove >=241 aligned KOSDAQ150 sessions through the latest
completed KRX session. If the direct KRX-index route is unavailable, the capture
continues to fail closed.


## 2026-09-21 post-merge live acceptance and official KRX fallback

PR #13 passed exact-head smoke and merged, but main capture run 35566151936
failed closed. FinanceDataReader `KRX-INDEX:2203` reached the KRX range path
and returned `LOGOUT`; the receipt remained `benchmark_fetch_empty:2203`.

The next H1 slice therefore adds an **official KRX Open API** fallback for the
KOSDAQ-series daily endpoint. It is used only after pykrx and the direct FDR KRX
index reader fail, selects the exact normalized index name `코스닥150`, and walks
the admitted KRX session calendar. The workflow passes `KRX_API_KEY` only through
the GitHub Actions secret environment.

Source identity is explicit:
`KRX_OPENAPI_KOSDAQ_DAILY_2203_NORMALIZED`.

The cache/source receipt remains normalized-only and never claims raw KRX bytes.
If the repository secret is absent, the API service is not approved, the response
shape changes, or any session identity is ambiguous, capture remains BLOCKED.


## 2026-09-21 A1 per-security source provenance

The successful 16-name Gold Set capture proved transport/coverage but still labeled
individual security history as an unresolved pykrx/FDR source. This A1 slice removes
that ambiguity without promoting the data:

- pykrx requests `adjusted=True` explicitly and records
  `PYKRX_ADJUSTED_TRUE_NORMALIZED`;
- the fallback calls `NAVER:<ticker>` explicitly through FinanceDataReader and
  records `FINANCE_DATAREADER_NAVER_CLOSE_PROXY_NORMALIZED`;
- ticker caches move to a new `adjusted-proxy-v1` namespace so old ambiguous
  caches cannot satisfy the new contract;
- each ticker cache requires a source sidecar; the capture archives its hash and
  propagates source identity into each snapshot/receipt.

The Naver fallback remains `NAVER_CLOSE_PROXY_UNREVIEWED`. Sidecars explicitly
set `raw_source_claimed=false` and `a3_reviewed=false`. Therefore this improves
A1 provenance only; it does not make the Korean capture consumable as a reviewed
A3 market snapshot and does not grant ER/selector/portfolio/order authority.
